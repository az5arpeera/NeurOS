- **D-039 · 2026-10-09 · "Use more of what we have": training crops later in each trial, and extra classes with a per-dataset softmax; test windows unchanged.** Implements the 6 Oct approval ("use more of what we have"). · Founders approved the idea; Claude set the rules below (founders may veto)
  - **Why:** E2 found the ceiling, not the warm-up speed, is what keeps cue-free accuracy below usable ([Q28](../open-questions.md)). Both levers add training signal without new data or new downloads.
  - **Crops** (`training_windows.crop_stride_s`; `registry.training_crop_starts`):
    - Extra training windows start at the test window and slide **later**, every stride, while a whole window still fits in the task. **Never earlier:** an earlier window sits closer to the class display and the cue's onset response, the shortcut D-030 removes.
    - So only datasets whose class leaves the screen early gain crops: Yang2025 (imagery 1.5–5.5 s: 4 crops at a 0.5-s stride) and BNCI2014-001 (2). Where the class stays up all task, the test window is already the latest one, and training is unchanged.
    - An epoch still counts one window per trial, so crops vary what each step sees without adding steps (early stopping and SWA keep their meaning).
  - **Extra classes** (`training_windows.extra_labels`: feet, tongue, both hands, rest):
    - One head over every class; **each training window's softmax runs over its own dataset's classes only.** A PhysionetMI window is never pushed away from "tongue", which PhysionetMI never recorded. Label smoothing is spread over the allowed classes.
    - From BNCI2014-001 (feet, tongue), PhysionetMI (both hands, feet, rest between trials) and Stieger2021 (both hands, rest).
    - Validation and test score **left vs right only**, on the left/right logits: a test window is never answered "feet".
  - **Unchanged:** validation and test windows (D-030's window), and their alignment. Training windows take the EA reference of the same session's test windows. Without the `training_windows` section, every step is E1's: tests check that training on a copy of the test windows reproduces E1 bit for bit.
  - **The cache isn't touched:** the window cutting lives in `neuros.data.training_windows`, outside the modules the recording cache's key hashes, so no dataset is re-prepared.
  - **E4-zs** (hold "feet" out and test the text head zero-shot) must leave feet out of `extra_labels`.
  - **Runs:** `configs/e2_crops.yaml`, `e2_multiclass.yaml` and `e2_crops_multiclass.yaml` are E2 with one change each, scored person by person against E2's pooled and warm-up numbers.
  - **Follow-up 10 Oct: result, and an artifact rule** ([results](../results/2026-10-10-d039-crops-multiclass.md)).
    - **Neither lever moves the ceiling:** +0.3 to +0.4 overall, within seed noise; the cue-free numbers at 120 s are unchanged. **E2's recipe stays the default** (no `training_windows` section). The code stays, for E4-zs and later checks.
    - **Artifact rule (`eval.pooled.screen_amplitude`, `8605be4`):** a newly cut training window is dropped if its RMS is more than **50×** its person's median window RMS, or if it isn't finite.
      - Genuine windows reach 10.6× and test windows 7.7×.
      - Two glitched Yang2025 crops at 7,200–7,650× broke the first crop runs: they set the input scale and the batch-norm statistics, and 4 of 5 models answered one class.
      - Windows that E1/E2 already trained on never go through the rule. Run reports count drops per dataset and per person.
    - **General amplitude guard (`eval.pooled.check_amplitude`):** closes the gap the incident left open. Any glitched training window, not only a new crop, could set the scale and the batch-norm statistics.
      - Before every model trains, `run_task` checks its training windows and its validation windows with the rule's measure: window RMS ÷ the person's median, over that set.
      - **It raises; it never drops.** A window above **50×**, a window with NaN/Inf samples, or a person with no signal raises `NeurOSDataError` naming the task, window, person, dataset and ratio, before anything trains. Data that passes is untouched, so E1/E2 runs stay bit-identical; a test trains the same task with and without the guard.
      - **Validation is checked too:** one glitch would dominate its person's validation loss, and so the epoch early stopping keeps. **Test windows aren't:** a glitched one costs only its own prediction.
      - **Checked on the laptop's smoke sets** (task, cue-only, D-039 training, E2 warm-up): all pass, at most 4.8×. The 10 Oct measurements didn't cover the full cue-only windows, so the next E1/E2 run on AWS is their first check.
      - **Cost:** one more chunked read of each model's training set, about 0.1 s per 1,000 windows (≈ 5 s for E2's 55k), against about 10 minutes of training.

- **D-036 · 2026-10-06 · Yang2025's files are 1000× too small as MOABB reads them: rescale by 1000 when harmonising.** A data-correctness fix of the same kind as D-035, found when E1 stopped on it. · Claude (data layer); **kept by the founders, 6 Oct**
  - **Result:** after the fix, all 153 Yang2025 recordings pass validation (all 153 failed before). E1's second run prepared 41 development people (24,592 cue-free windows) without a stop.
  - **What happened:** E1 (started 5 Oct, 21:16 UTC) prepared PhysionetMI, Dreyer2023, Stieger2021, Lee2019_MI and Cho2017, then stopped at Yang2025's first recording: "every channel's std is below 0.1 µV … the data is probably still in volts". The validation lane failed all 153 Yang2025 recordings the same way. The idle auto-stop then shut the machine down as designed.
  - **Evidence (6 Oct):**
    - **The files declare µV.** All 153 two-class files declare the same physical unit on all 64 channels: the two bytes `3F 56`, "?V". A "?" stands in for a character the writer couldn't encode, and the micro sign is the only fit: an ASCII "nV" would have survived. The raw motor channels sit 1–8.5 mV from zero, a normal DC offset; in nV they would be implausibly small.
    - **The publisher documents the range.** The paper's Table 1 ([Yang et al. 2025](https://doi.org/10.1038/s41597-025-04826-y), open access as PMC11930978) gives the Neuracle amplifier's input range as ±375 mV with a 24-bit ADC. The files' physical range is ±375,000, which is exactly that in µV. In nV it would be ±375 µV.
    - **The conversion is off by 1000.** MNE doesn't recognise "?V", so it passes the values through as volts. MOABB 1.7's loader then multiplies by 10⁻⁹, assuming nanovolts ("Neuracle BDF files use nV"). That leaves µV values 1000× too small.
    - **The spectrum is EEG-shaped and about 1000× too low.** It has 1/f fall-off and a mu peak near 10 Hz, and sits 690–2000× below Dreyer2023's and Lee2019_MI's at every frequency from 4 to 45 Hz (C3/Cz/C4 after common average; two development people each). ×1000 puts it level with them (10 Hz: 0.8–1.4 vs 1.6 µV/√Hz).
    - **Typical amplitude:** a median of 0.003 "µV" across the 153 recordings becomes ~3 µV. The six datasets that pass have medians of 2.9–4.2 µV.
    - Unlike Cho2017's, this factor matches the publisher's documentation, so `unit_scale` isn't listed as unverified for Yang2025 (9d47465 still listed it; E1's second run is stamped with that commit, and the difference is only the label, which isn't part of the cache key).
  - **Applied:** registry `unit_scale = 1000` for Yang2025, the mechanism D-035 added (bounded to [0.001, 1000]; part of Yang2025's cache key only, so the five datasets E1 had prepared stay cached).
  - **Effect:** none on aligned models (EEGNet + EA per session divides out the scale). Without it Yang2025 can't be used at all: every recording fails validation. It also matters for the thresholds and unaligned baselines, as for D-035.
  - **To report upstream (founders' call):** MOABB's Yang2025 loader assumes nV for files that declare "?V". The same files read through MOABB are 1000× too small for every user.

- **D-035 · 2026-10-05 · Cho2017's files are 32× too large: rescale by 1/32 when harmonising.** A data-correctness fix found by validation on AWS. · Claude (data layer); **kept by the founders, 5 Oct**
  - **Result:** after the fix, all 52 Cho2017 recordings pass validation (they failed 3 of 52 before).
  - **Evidence (5 Oct):**
    - Read as µV, every one of the 52 recordings has a typical 4–30 Hz amplitude of 160–260 µV, and every window exceeds 500 µV peak to peak. Three people (12, 39, 48) fail the units check outright (> 200 µV).
    - **Common average doesn't explain it:** 107–143 µV after it.
    - **The spectrum is EEG-shaped**, falling with frequency and with an alpha peak at 10 Hz, but **20–26× Dreyer2023's at every frequency** from 4 to 30 Hz (C3/Cz/C4, two people each). A unit error scales everything; noise wouldn't keep EEG's shape.
    - **The paper's own rule only fits a smaller scale:** a trial was bad if its 8–30 Hz signal exceeded ±100 µV. At our reading almost every trial would fail; at 1/32 only artifacts do.
    - **The mechanism:** BioSemi's raw step is 31.25 nV = 1/32 µV, so the files hold raw steps, which MOABB reads as µV.
    - The publisher's documentation doesn't state the unit. The factor is therefore inferred, and `unit_scale` is listed as unverified for Cho2017.
  - **Applied:**
    - registry field `unit_scale` (default 1.0, bounded to [0.001, 1000]); Cho2017 = 1/32;
    - `harmonize_raw` multiplies by it;
    - it's part of the cache key, like every data-shaping field.
  - **Effect:**
    - **None on aligned models** (EEGNet + EA, E1): per-session Euclidean alignment divides out a session's scale.
    - **It matters for:** validation thresholds, unaligned Riemannian baselines, and the online quality gate, whose thresholds §7.1 tunes on Cho2017's non-task recordings.
    - Without it, the three failing people would have stopped E1 at data preparation.

- **D-029 · 2026-10-03 · Deep-model and training details, fixed in code (Day 3).** These fill in what architecture §6.1, §6.4 and E0 left open:
  - **Encoder:** EEGNet exactly as published (Lawhern 2018).
    - Keras's batch-norm settings (running statistics move 1% per step, ε = 1e-3), Glorot initialisation, no convolution biases.
    - Max-norm caps: 1 on each spatial filter, 0.25 on each class of the head.
    - F1/D/F2 = 16/2/32 with a 64-sample temporal kernel (§6.1), then our 64-d embedding and the linear head.
    - **20,002 parameters** for 22 channels × 2 s.
  - **Training recipe:**
    - batches of 8 people × 8 windows, class-balanced within each person;
    - AdamW (lr 1e-3, weight decay 0.05); the learning rate follows a cosine down to 0.
    - **SWA** = the plain average of the weights after each of the last 25% of the run's epochs.
    - **Early stopping** (optional, validation people only): the run then ends at the best validation epoch, and SWA averages the last quarter before it.
    - **Batch-norm statistics are always recomputed for the final weights** (one shuffled pass over the training windows). Averaged weights need their own statistics, and running statistics that move 1% per step lag the weights.
  - **Input scale:** the inputs of each fold are divided by one number, the RMS of its training windows (training people only, principle 2).
  - **EA reference: one per recording session** (it was one per person on Day 2).
    - It's the paper's protocol, and the offline twin of the online engine, which starts a new reference every time the headset goes on.
    - Measured on BNCI2014-001 with the Riemannian baselines: per session and per person differ by **< 1 point**, so the Day-2 numbers stand.
    - Amends §5's "per person" (🔒).
  - **E0 has a second config with the paper's 4-s window** (cue + 0–4 s), besides our 2-s contract window (cue + 0.5–2.5 s), so a shortfall could be traced to the window (a protocol choice) or to a bug. The 2-s run passed the pipeline check (75.0%). The 4-s run (4 Oct) gave 83.7%, largely by decoding the on-screen cue. - **D-028 · 2026-10-03 · Signal-chain details, fixed in code (Day 2).** These fill in what architecture §4.2 and §5 left open, without changing the contract:
  - **Band-pass:** Butterworth **order 4 per edge** (8 poles). Measured at every native rate in scope (160–1000 Hz): ≈ 35 ms delay at 10 Hz, 99% settled within 0.22 s, ≥ 30 dB down at 64 Hz. Order 2 would halve the delay but leave only 15–29 dB at 64 Hz, and the band-pass is also the resampler's anti-alias filter.
  - **Notches:** 50 and 60 Hz, **Q = 30**.
  - **Start-up:** the filter starts in its steady state for the first sample, so DC offsets don't ring. Windows starting within **0.5 s** of a (re)start are flagged.
  - **Resampling:** **linear interpolation on timestamps** (≤ 1 dB loss at 30 Hz; identical offline and online).
  - **CAR:** applied **per window, after the channel subset is chosen** (exact, because CAR commutes with the linear chain).
  - **Riemannian baselines:** OAS covariances; with CAR, a projection onto the zero-sum subspace (covariances must be positive definite).
  - **Evidence:** offline and streaming outputs are bit-identical for any chunking (the golden parity test).
